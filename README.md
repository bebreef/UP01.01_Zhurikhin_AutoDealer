# Автодилерский центр

Учебный проект по УП.01.01. WPF-приложение для каталога автомобилей, работы с клиентами, сделками и учётными записями сотрудников.

## Требования

- Windows, Visual Studio 2022 с компонентом разработки классических приложений .NET.
- .NET Framework 4.7.2, Entity Framework 6.2.
- SQL Server 2022 и SQL Server Management Studio.
- Установленные Microsoft Word и Excel для экспорта отчётов. PDF создаётся через Word.

## Запуск

1. В SSMS подключиться к своему SQL Server и выполнить `db/schema.sql`. Скрипт создаёт новую БД `DB_Zhurikhin_AutoDealerManagement`; существующую базу он не удаляет. Не запускать его поверх рабочей БД.
2. Открыть `WPF_Zhurikhin_AutoDealer.sln` и восстановить NuGet-пакеты.
3. В `WPF_Zhurikhin_AutoDealer/App.config` изменить `data source` в строке подключения на имя своего SQL Server. Авторизация БД использует учётную запись Windows.
4. Собрать решение и запустить приложение.

SQL-скрипт содержит снимок учебных данных. Пароли учётных записей хранятся как хэши; открытые пароли в README не публикуются. Для входа используйте выданные автором учебные реквизиты. Самостоятельная регистрация создаёт роль «Пользователь».

## Возможности и роли

| Роль | Возможности |
| --- | --- |
| Пользователь | Каталог, поиск, фильтры, сортировка, заявка на покупку с резервом, смена своего пароля |
| Администратор | Автомобили, клиенты, сделки, управление сотрудниками, отчёты |
| Менеджер по продажам | Добавление, изменение и удаление разрешённых записей автомобилей, клиентов и сделок |
| Руководитель | Просмотр данных и отчёты |
| Мастер-приемщик, кладовщик, автомеханик | Просмотр, поиск, фильтры и сортировка внутренних списков |
**Пока готовы только роли Пользователя и Администратора, остальные все еще в разработке**

Список ролей загружается из актуальной БД, содержащей семь ролей. Названия ролей используются при проверке доступа.

Покупатель подтверждает автомобиль, цену и контактные данные. Создаются контактная запись клиента и резервная сделка, назначенная первому активному менеджеру по продажам по EmployeeID. Менеджер завершает оформление. Реальной оплаты нет. При каждой заявке создаётся отдельная запись клиента; история заказов покупателя в интерфейсе не предусмотрена.

Договоры имеют статусы «Черновик», «Зарезервирован», «Исполнен», «Отменен». Исполненные и отменённые договоры неизменяемы. Состояние автомобиля при резервировании, продаже и отмене резерва изменяют триггеры БД. Удалять договоры можно только в статусе «Черновик».

Каскадное удаление в приложении: автомобиль или клиент удаляется вместе со связанными черновиками сделок в одной транзакции, после подтверждения. Наличие других договоров или сервисных заказов запрещает удаление. В схеме БД также есть каскадные связи состава поставки и сервисного заказа. Сотрудника со связанными документами можно отключить вместо удаления.

Отчёты учитывают только исполненные сделки, позволяют выбрать период, сотрудника и вид диаграммы. DOCX, PDF и XLSX содержат сформированные данные и диаграмму; итог XLSX рассчитывается формулой.

## Интерфейс

Боковое меню выезжает при наведении на левый край окна. Есть светлая и тёмная темы; выбор сохраняется в `%LOCALAPPDATA%\AutoDealer\theme.txt`. После трёх неверных попыток входа появляется капча. Для удаления, выхода и необратимого изменения статуса договора предусмотрены подтверждения.

## Структура

- `WPF_Zhurikhin_AutoDealer/Pages/` — страницы XAML и обработчики C#.
- `WPF_Zhurikhin_AutoDealer/Themes/` — словари тем.
- `WPF_Zhurikhin_AutoDealer/Model1.edmx` — EF-модель.
- `WPF_Zhurikhin_AutoDealer/Core.cs` — контекст и текущий пользователь.
- `WPF_Zhurikhin_AutoDealer/PasswordHelper.cs` — проверка и хэширование паролей.
- `WPF_Zhurikhin_AutoDealer/Images/` — ресурсы, включённые в WPF-проект.
- `res/` — копия исходных иконок по структуре задания. При замене иконок обновлять обе папки.
- `db/schema.sql` — схема, ограничения, триггеры и учебные данные.
